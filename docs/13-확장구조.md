# 확장 구조 — 100층에서 1000층으로

## 문제

100층을 "이렘의 시작"으로 정해두면 그 위로 올라갈 수 없다.
2부·3부를 내려면 층 체계 자체가 확장 가능해야 한다.

## 해답 — 탑은 지층이다

> **이렘 이전에 다른 세계가 있었다.**
> 그 세계도 멸망했고, 그 위에 이렘이 세워졌다.

탑 전체는 **겹겹이 멸망한 세계들의 지층**이다.
"오를수록 과거로 간다"는 규칙이 1000층까지 그대로 유지된다.

| 구간 | 세계 | 부 |
|---|---|---|
| 1~100 | **이렘** | 1부 |
| 101~200 | 이렘 이전의 세계 | 2부 |
| 201~300 | 그 이전 | 3부 |
| … | … | … |
| 901~1000 | 최초의 세계 | 최종부 |

1000층 = 모든 것의 시작이자 **최초의 멸망**.

이 구조가 상위 질문 하나를 만든다.
**왜 세계는 계속 멸망하는가.** 그것이 전체 시리즈의 질문이 된다.

## 각 부의 독립성

각 부는 **100층으로 완결된다.** 자체 반전과 자체 엔딩을 갖는다.
2부를 안 해도 1부만으로 이야기가 끝난다. 라이브 서비스의 필수 조건이다.

| 부마다 새로 만드는 것 | 부마다 유지하는 것 |
|---|---|
| 세계 이름, 시대 구분 5개 | 등급 = 기억의 선명도 |
| 생업 목록 (12~20종) | 역할 5종 (수호/저항/헌신/탐구/도피) |
| 캐릭터 풀 전체 | 본디·개화·승급 시스템 |
| 고유 반전 1개 | 뜰, 명부, 층 공략 구조 |

**시스템은 재사용하고 내용만 갈아 끼운다.**
`10-시스템-구조.md`의 데이터 주도 설계가 여기서 값을 한다 — 2부는 JSON 교체가 대부분이다.

## 반전의 사다리

각 부는 **플레이어가 당연하게 여긴 전제 하나**를 뒤집는다.
같은 수법을 반복하면 안 되므로 뒤집는 대상을 매번 바꾼다.

| 부 | 뒤집는 것 | 1부 예시 |
|---|---|---|
| 1부 | **요청의 내용** | 구해 달라 → 기억해 달라 |
| 2부 | 요청의 **발신자** | 탑이 보낸 것이 맞는가 |
| 3부 | 응답자의 **정체** | 플레이어는 정말 바깥 존재인가 |
| … | 되살리기의 **결과** | 실패한 것이 맞는가 |

2부 이후는 후보일 뿐이다. 1부를 내고 반응을 본 뒤 정한다.
**미리 확정하지 않는다.** 확정하면 1부 집필이 그쪽으로 끌려간다.

## 잔상 이월

전 부의 잔상을 전부 데려가면 밸런스가 무너지고, 새 캐릭터를 뽑을 이유가 없어진다.

> **명부는 영구히 남는다. 데려가는 것은 제한한다.**

| 항목 | 규칙 |
|---|---|
| 명부 | 전 부의 모든 기록이 영구 보존. 삭제되지 않는다 |
| 이월 인원 | 부당 **최대 5명** |
| 이월 후 | 성급과 스킬은 유지. **층 조건 열쇠로는 쓸 수 없다** |

마지막 항목이 핵심이다.
이월 잔상은 강하지만 **그 세계 사람이 아니라서** 시대·생업 조건을 못 맞춘다 (`06-층-공략.md`).

- 서사적으로 맞다 — 그는 이 세계를 모른다
- 밸런스가 지켜진다 — 신규 캐릭터를 뽑아야 할 이유가 남는다
- 이월 선택이 어려워진다 — 전투력이냐 애착이냐

## 성급 상한

**10성 상한은 부가 바뀌어도 올리지 않는다.**

승급이 2배씩 누적되는 구조라(`08-승급.md`) 상한을 11로만 올려도 필요 재료가 두 배가 된다.
12성, 13성으로 올리면 지수적으로 터진다.

대신 부마다 **다른 축**을 연다.

| 부 | 새로 열리는 축 |
|---|---|
| 1부 | 본디 · 개화 · 승급 |
| 2부 | 「겹」 — 두 세계의 잔상을 뜰에서 엮는 새 인연 계열 |
| 3부 | (미정) |

세로로 늘리지 않고 가로로 넓힌다.

## 구현 시 지켜야 할 것

지금 1부를 만들면서 **미리 해둬야 확장이 가능한 것들**이다. 나중에 고치면 비싸다.

```csharp
// 층 번호는 절대 100으로 나누지 말고 세계 개념을 명시적으로 둔다
struct FloorId {
    int world;   // 1 = 이렘
    int floor;   // 1~100
    int Absolute => (world - 1) * 100 + floor;
}
```

- **세이브에 `worldId` 를 처음부터 넣는다.** 1부만 만들 때도 넣는다
- 시대·생업·역할을 **enum이 아니라 데이터 ID**로 다룬다. enum은 2부에서 못 늘린다
- 명부는 세계별로 분리 저장하되, **조회는 통합**되게 만든다
- 생성기 시드에 `worldId` 를 섞는다 — 안 그러면 2부에서 1부와 같은 잔상이 나온다

마지막 항목은 놓치기 쉽다. `05-고유성.md`의 시드 기반 생성이 세계마다 달라야 한다.
