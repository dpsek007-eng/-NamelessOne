# 아트 방향 — 부품 조합

## 전제 두 가지

**1. 유니티는 그림을 만들지 않는다.**
불러와서 표시할 뿐이다. 그림은 Aseprite·Photoshop·Blender·이미지 생성 툴로 밖에서 만들어 넣는다.

**2. 손으로 그릴 수 없다.**
무명 잔상은 수십만 명이다 (`05-고유성.md`). 외주도 불가능하다.
**아트도 텍스트와 똑같이 부품 조합이어야 한다.**

## 스타일 — 실루엣

설정이 스타일을 정해 준다.

> 잔상은 사람이 아니다. **탑이 기억하는 만큼만 형태를 갖춘다.**

- 짙은 실루엣 + 강조색 하나
- 팔은 몸통보다 밝은 톤 — 안 그러면 겹쳐서 덩어리가 된다
- **발끝이 흐려진다.** 아래에서 위로 사라지는 존재다

실루엣은 부품 조합에 가장 적합한 형식이기도 하다. 형식과 설정이 일치한다.

## 조합 구조

```
체형(역할 5종) → 의복(계층 11종) → 소품(생업 47종) → 강조색 → 흐려짐
```

| 층 | 종수 | 결정 요인 |
|---|---|---|
| 체형·자세 | 5 | 역할 (수호/저항/헌신/탐구/도피) |
| 의복 | 11 | 계층 (`02-캐릭터-시스템.md`) |
| 소품 | 47 | 생업 |
| 강조색 | 20+ | 개체별 |

`tools/sprite_gen.py` · 48×64 도트 · 배율 지정 가능

## 품질 — 정직하게

현재 코드 생성물은 **프로토타입 등급**이다.

| | 상태 |
|---|---|
| 실루엣 | 쓸 만하다. 두건 쓴 술사·성직은 형태가 읽힌다 |
| 소품 | **부족하다.** 납작한 도형이라 물건으로 안 읽힌다 |

`10-시스템-구조.md`의 **0~4단계 검증용으로는 충분하고, 출시용으로는 부족하다.**
4단계(뜰 UI)에서 "이 게임이 재미있는가"를 판단하는 데는 지장이 없다.

## 실제 제작 — 하이브리드

| 방식 | 판단 |
|---|---|
| 코드 생성 그대로 | 프로토타입 전용 |
| 아티스트가 캐릭터를 전부 | **불가능** — 수십만 명 |
| **전승 40명 손그림 + 무명은 부품 조합** | ⭐ 권장 |

### 핵심 — 캐릭터가 아니라 부품을 발주한다

아티스트에게 "캐릭터를 그려 주세요"가 아니라 **부품 라이브러리**를 의뢰한다.

| 부품 | 장수 | 비고 |
|---|---|---|
| 체형·자세 | 5 | 역할별 |
| 의복 | 11 | 계층별. 옷단 높이 규격 고정 |
| 머리·두건 | 6 | 맨머리·두건·투구·모자 등 |
| 소품 | 47 | 생업별. 손 위치 앵커 기준 |
| **합계** | **≈ 70장** | |

70장으로 수십만 명이 나온다. 절차 생성 캐릭터가 있는 게임들이 실제로 쓰는 방식이다.

**지금 코드의 값어치는 그림이 아니라 조합 규칙이다.**
어떤 부품이 몇 종 필요한지, 어디에 붙는지가 정의돼 있어 **그대로 발주서가 된다.**

### 규격 (아티스트 전달용)

```
캔버스      48 × 64 px
중심선      x = 24
머리        y 7~18
어깨        y 21
허리        y 32
옷단        계층별 40~57 (HEM 표)
발          y 61
손 앵커     역할별 5좌표 (sprite_gen.py hand 변수)
흐려짐      하단 16px 알파 그라데이션
```
